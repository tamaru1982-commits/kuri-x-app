# 引き継ぎまとめ: 暗号資産トレード支援システム

このドキュメントは、Claude(チャット)で設計・実装したプロジェクトを
VSCode版Claude Codeに引き継ぐためのまとめです。

## 1. プロジェクトの目的

暗号資産(仮想通貨)を対象に、複数の情報源からシグナルを検知してDiscordに通知する
個人用トレード支援システム。**自動売買は行わず、通知・記録・分析のみ**。

運用方針:
- **現物取引が前提**(レバレッジは今回は使わない。強制清算リスクを避けるため)
- **少額(1万円)からコツコツ増やす**方針。大きく張って一発を狙う設計ではない
- 「買いシグナル」だけでなく「売り(利確/損切り)タイミング」も通知する
- 感覚的な判断より、ルールベースの通知に従うことで感情的な判断(リベンジトレード等)を避ける

## 2. 実装済みの構成(Phase1〜3)

### Phase1: 基本のシグナル通知
| ファイル | 役割 |
|---|---|
| `crypto_signal_notifier.py` | CoinGecko(無料)の価格からSMAクロス+RSIでLONG/SHORT判定・通知 |
| `x_signal_notifier.py` | X(旧Twitter)の特定アカウントの投稿をキーワード監視・通知 |
| `nfp_pattern_analysis.py` | 雇用統計(NFP)の過去パターンを集計(月1回手動実行) |
| `economic_calendar_reminder.py` | NFP/CPI/PCE発表前日にリマインド通知(`nfp_reminder.py`の後継、統合版) |

### Phase2: 分析・リスク管理
| ファイル | 役割 |
|---|---|
| `db_utils.py` | 全体の共有SQLite DB(`trading_system.db`)。シグナル履歴・トレード日誌を管理 |
| `risk_utils.py` | ポジションサイズ・損切りラインの参考計算(**要見直し、下記4章参照**) |
| `accuracy_tracker.py` | 過去シグナルの的中率を自動検証(1h/24h後)、週次でレポート |
| `confluence_checker.py` | 複数ソースのシグナルが同方向で重なったら強調通知 |
| `correlation_report.py` | 追跡資産間の相関を週次で通知(集中リスクの可視化) |
| `journal_add.py` / `journal_close.py` / `journal_report.py` | 手動トレード記録CLI・成績集計 |

### Phase3: ポジション監視(売りタイミング)
| ファイル | 役割 |
|---|---|
| `position_monitor.py` | journalに記録した保有中ポジションを監視し、利確(+8%)/損切り(-5%)ラインで通知 |

各`.py`に対応する`.yml`(GitHub Actions workflow)も用意済み。

## 3. セットアップに必要なAPIキー(Secrets)

| 名前 | 取得元 | コスト |
|---|---|---|
| `DISCORD_WEBHOOK_URL` | Discordのチャンネル設定 | 無料 |
| `X_BEARER_TOKEN` | console.x.com (Developer Portal) | 従量課金(個人利用なら月数ドル程度) |
| `FRED_API_KEY` | fred.stlouisfed.org | 完全無料・即時発行 |

GitHub側の設定:
- Settings > Secrets and variables > Actions に上記を登録
- Settings > Actions > General > Workflow permissions を「Read and write permissions」に変更
  (状態ファイル・DBの自動コミットに必要)

## 4. VSCodeで対応してほしい未実装・要修正事項

優先度が高い順に並べています。

### 4-1. risk_utils.pyの簡略化(要修正)
**現状の問題**: 口座残高($1000固定)を前提にドル建て金額を通知しているが、
実際の運用資金(1万円スタート)と合っていない。また複数銘柄で同時にシグナルが出ると
「口座の33%」のような表示が重複し、合計が100%を超える矛盾がある。

**修正方針**:
- ドル/円建ての金額表示をやめ、「口座資金の◯%まで」という比率ベースの
  シンプルな注意書きに変更する
- 複数銘柄同時シグナル時に、合計エクスポージャーが資金を超えないような
  按分ロジックを検討する(または「同時に複数銘柄は追わない」という運用ルールにする)

### 4-2. クジラ(大口)監視機能の追加(新規)
**背景**: 大口(クジラ)の取引所への資金移動は、売買の前兆シグナルとして意味がある。
Whale Alert公式APIは有料だが、**Whale AlertのXアカウント(`@whale_alert`)の投稿を
`x_signal_notifier.py`と同じ仕組みで監視すれば、ほぼ無料で実現できる**。

**実装イメージ**:
- `whale_signal_notifier.py`を新規作成(`x_signal_notifier.py`がベース)
- 監視対象を`whale_alert`アカウントに変更
- キーワードマッチではなく、「金額+取引所名+方向(into/out of)」を正規表現で抽出
- 解釈の目安:
  - BTC/ETH等を取引所へ送金 → 売り圧力の可能性(弱気)
  - ステーブルコイン(USDT/USDC)を取引所へ送金 → 買い準備の可能性(強気)
  - 取引所からの出金 → 長期保有の意思表示(強気)
- `db_utils.py`に`source="whale_flow"`として記録すれば、
  既存の`confluence_checker.py`が自動的に「テクニカル+X発言+クジラ」の一致も検知できる
- 発展形として、Arkham Intelligence API(2026年2月公開、詳細な料金体系は要確認)との連携も
  将来的に検討の余地あり

### 4-3. ステータス確認用の簡易ダッシュボード(新規)
**背景**: 現状はDiscordの通知が来た瞬間しか状況を確認できない。
「今どうなっているか」をいつでも見れるようにしたい。

**実装イメージ**:
- 各通知スクリプト実行時に、最新のシグナル状況・的中率・保有ポジションなどを
  1枚のシンプルなHTMLとして自動生成
- **GitHub Pages**(無料)でホスティングし、スマホのホーム画面にブックマークすれば
  簡易アプリのように使える

### 4-4. チャートパターン認識(将来検討・優先度低)
逆三尊(インバースヘッドアンドショルダーズ)のようなチャートパターン検出は、
実装難易度が高く(極大値・極小値の検出、複数条件のルール化)、
主観的判断の余地も大きいため、**現時点では実装を見送る**ことで合意済み。
まずはSMA/RSIベースのシグナル精度を`accuracy_tracker`で検証し、
データが貯まってから検討する。

## 5. 動作確認・デバッグでやってほしいこと

1. リポジトリ初期化、`.github/workflows/`への各`.yml`配置
2. GitHubにprivateリポジトリを作成してpush
3. 上記Secretsの登録、Workflow permissionsの変更
4. ローカルで`pip install -r requirements.txt`後、各スクリプトを試験実行
5. 各Actionsをworkflow_dispatchで手動実行し、正常に動くか確認
   (CoinGeckoのレート制限、X APIのレスポンス形式の実際の挙動などは
   実行してみないと分からない部分があるため、ここでの反復調整が必要)
6. 上記4章の項目について、優先順位を相談しながら実装

## 6. 全体を通じての注意事項

- 投資助言ツールではなく、あくまで通知・記録・分析支援ツール
- 自動売買機能は搭載しない方針(通知のみ)
- レバレッジは現時点では使わない前提(現物・コツコツ運用)
- 「月◯万円」のような高いリターン目標より、「退場しないこと」を優先する方針で
  ここまで設計してきている

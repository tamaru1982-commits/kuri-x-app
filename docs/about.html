これは何のツールか

暗号資産(仮想通貨)を対象に、複数の情報源からロング/ショートの参考シグナルを検知して Discordに自動通知する個人用ツールです。

  • 自動売買は一切行いません。通知・記録・分析支援のみです
  • 現物取引が前提です(レバレッジ・信用取引は使いません。強制清算リスクを避けるため)
  • 少額からコツコツ増やす方針で、「大きく張って一発を狙う」設計ではありません
  • 感覚的な判断より、ルールベースの通知に従うことで感情的な判断(高値掴み・狼狽売りなど)を避けることを目的としています

LONG / SHORT / 様子見 の読み方

LONG 買い候補、または保有継続を支持するサイン

SHORT 空売りのサインではありません。現物取引が前提のため、 「保有中なら売却/未保有なら買い見送り」という意味で扱っています。

押し目 下記「crypto_dip」参照。トレンドとは無関係の買い候補サインです

様子見: 明確なサインが出ていない状態です

シグナルソース一覧

ダッシュボードの「ソース」欄に表示される略称と、それぞれの判定根拠です。

techcrypto_technical

CoinGeckoの価格(日足・過去120日分)から、SMA9とSMA21のクロス + RSI(14)で判定する トレンドフォロー型シグナル。SMA短期が長期を上抜けた瞬間(ゴールデンクロス)で、 かつRSIが買われすぎ(70)でなければLONG。下抜けた瞬間(デッドクロス)で、 かつRSIが売られすぎ(30)でなければSHORT。

性質上、「すでにトレンドが始まった後」に出るため、安値で仕込むタイミングの検知には向きません (下記 dip 参照)。同一銘柄・同一方向は既定180分のクールダウンで再通知を抑制しています。

2026年8月29日に時間軸を1時間足から日足に変更しました。 以前は7日分を取得していたためCoinGeckoが1時間足を返しており、SMA9/21は 「9時間平均と21時間平均」を意味していました。「1〜3日以内に+5%」という運用に対して 短すぎ、クロスが週7.7回/銘柄も発生していました。現在は本来想定される 「9日平均と21日平均」で判定しています。
あわせて「トレンド継続中も出す」から「クロスした瞬間だけ出す」へ変更しました。 以前は「短期線が長期線より上にある」という状態で判定していたため、 同じ相場が続く限り何度もシグナルが出ていました(実測でETH LONGが5回、XRP SHORTが5回)。 売買タイミングとして意味を持つのはクロスした瞬間だけなので、そこに絞っています。
レンジ相場ではクロスが小刻みに反転する「ダマシ」が起きやすいため、 クロスを検知した回はいったん保留し、次の実行でもまだ同じ側にいれば確定という 2段階にしています(押し戻された場合は見送られ、通知されません)。 また、実行が遅延・欠落してもクロスを取りこぼさないよう直近数本さかのぼって探しつつ、 一度処理したクロスは発生時刻で記録して二度と再通知しないようにしています (これが無いと、クールダウンが切れるたびに同じクロスを繰り返し通知してしまいます)。
dipcrypto_dip

SMAのトレンド方向とは無関係に、RSIが売られすぎ圏(既定30以下)に入ったこと自体を 現物の押し目買い候補として通知します。ダウントレンド中でtechがSHORTを出していても、 dipは独立して発火します。「安く仕込みたいが、トレンドフォローのLONGだと高値掴みになる」という 矛盾を解消するために追加したシグナルです。

xx_post

指定したXアカウントの投稿を、キーワード(「買い」「上昇」「強気」/「売り」「下落」「弱気」等)で 単純にマッチングして判定します。テクニカル分析ではなく、その人の発言をそのまま拾っているだけです。 皮肉・引用・否定文(例:「買いではない」)なども拾ってしまう可能性があります。

whalewhale_flow

Whale Alert(@whale_alert)の投稿から、大口資産の取引所への入出金を検知します。

  • BTC/ETH等の主要資産が取引所へ入金 → 売り圧力の可能性(SHORT)
  • ステーブルコイン(USDT/USDC等)が取引所へ入金 → 買い準備の可能性(LONG)
  • 資産が取引所から出金 → 長期保有の意思表示(LONG)

取引所名は既知の主要取引所リストとの照合で判定しており、DeFiプロトコルや個人ウォレット間の移動は対象外です。

移動額(USD)に応じて4段階の簡易ランクを付けて通知します(Whale Alert自体が既に一定規模以上の 移動のみを投稿しているため、その中でのさらなる大小比較です):

  • 🐟 小口: 〜$10M未満
  • 🐬 中口: $10M〜$50M未満
  • 🐋 大口: $50M〜$100M未満
  • 🐳 超大口(メガクジラ): $100M以上

これまでに検知したクジラの規模分布(ざっくり):

🐳 超大口(メガクジラ)2件 (40.0%)
🐋 大口3件 (60.0%)
🐬 中口0件 (0.0%)
🐟 小口0件 (0.0%)

合計5件(金額判明分)を集計。金額不明2件は除外。あくまで簡易集計で、傾向をざっくり把握するためのものです。

macromacro_pattern

米雇用統計(NFP)・金・ドル指数・AI株(NVDA)・S&P500・VIX(恐怖指数)・原油(WTI)・ FF金利(FOMC政策金利)の月次データから、「雇用統計が直近3ヶ月平均比で上振れ/下振れ」× 「上記6指標の当月の動きから多数決で算出したリスクセンチメント(リスクオン/オフ)」の 4パターンについて、過去の翌月BTC値動きを集計。現在の環境が該当するパターンで、 サンプル数が十分(既定10件以上)かつ偏りが大きい(既定65%/35%超)場合のみ通知します。

月次×少数パターンでの集計のため1パターンあたりのサンプル数は数十件程度に留まり、 他のシグナルより統計的根拠は明確に弱いです。必ず参考情報として扱ってください。 また暗号資産の価格データは2014年9月頃までしか遡れません。
confconfluence

tech・x・whaleのうち、直近6時間以内に複数のソースが同じ資産・同じ方向のシグナルを出した場合に 強調通知します。異なる情報源が同じ結論に達している方が、単独のシグナルより参考情報としての 重みが増す、という考え方です(macro・dipは性質が異なるため対象外)。

各情報の取得タイミング

すべてGitHub Actionsの定期実行(cron)で自動的に動いています。時刻は日本時間(JST)の目安です。 実行する分は「検知 → 一致判定 → 建玉 → 監視 → 表示 → 検証」の順に並べたうえで、 それぞれの実測実行時間の2倍以上の間隔を空けてあり、 2つの処理が同時に走らないようにしています(理由は下の注記)。

機能実行タイミング(毎時)実測設定ファイル
tech / dip(価格取得・判定)00分・30分約150秒crypto_signal.yml
whale(クジラ監視)06・21・36・51分(指定時間帯のみ)約15秒whale_signal.yml
conf(複数ソース一致確認)09分・39分約15秒confluence_checker.yml
ペーパートレード記録12分・42分約15秒paper_trader.yml
ポジション監視15分・45分約20秒position_monitor.yml

なぜ実行時刻をずらしているか: 各処理は結果を同じデータベースファイル(trading_system.db)に書き込み、 リポジトリにコミットして保存しています。このファイルはバイナリ形式のため、 2つの処理が同時に書き込むとgitが自動でマージできず、後からコミットした側が丸ごと弾かれ、 その回の検知結果が記録されないまま消えてしまいます。 実際に2026年8月28日、クジラ検知が1件この理由で失われました。 現在は「実行時刻を実測時間の2倍以上ずらす」「同じグループの処理は同時に動かない設定にする」 「万一弾かれても最新を取り込んで再試行する」の3段構えで防いでいます。 なお同時に動かない設定は、3つ以上が一度に重なると待機中のものが取り消される仕様のため、 そもそも重ならないよう実行時刻の間隔で担保することを主にしています。
GitHub Actionsのschedule実行は「その時刻ちょうど」に必ず動く保証がなく、GitHub側の負荷状況で 数十分〜数時間単位で遅れることがあります(無料枠での既知の制約です)。通知が来るのが遅いと感じても、 異常とは限りません。

変更したい場合は、各.github/workflows/*.yml内のcron:の行を書き換えてpushします。 cron書式は「分 時 日 月 曜日」(UTC基準)です。GitHubのリポジトリ画面から該当ファイルを開き、 鉛筆アイコンで直接編集してコミットすることもできます。

リスク管理の表示について

通知に添えられる「損切り目安」は、価格からの一定率(既定3%)で計算した参考値です。 また「1トレードの損失許容は口座資金の◯%まで」という表示は、口座残高や通貨単位に依存しない 比率ベースの目安です(以前はドル建て金額・数量を計算していましたが、実際の運用資金[円]と 価格データ[ドル]の通貨が一致しない問題があったため、比率表示のみに変更しました)。

複数銘柄で同時にLONG/SHORTシグナルが出た場合は、「同時に追うのは基本1銘柄まで」という 注意書きが自動的に追加されます。資金を分散しすぎないようにするためのシンプルな運用ルールです。

的中率について

各シグナルについて、発生から約1時間後・約24時間後の価格を自動取得し、当たっていたかを記録しています。 ダッシュボードにはソース別(どのシグナルが効いているか)と 銘柄別(どの通貨で効いているか)の2つの表を出しています。 判断に使うのは基本的にソース別の方です。銘柄別はサンプルが細かく分かれるため、 1つ1つのマスの件数がどうしても少なくなります。

「的中」の基準: 単に方向が合っていただけでは的中に数えません。 往復手数料(既定0.3%)を超えて動いた場合のみ的中としています。 +0.01%の微動まで的中に数えると、実際には手数料負けする動きまで「当たり」になってしまい、 的中率が実態より甘く出るためです。

2026年8月29日の判定ルール変更以降のシグナルのみを集計しています。 同日にtechを「トレンド継続中も出す」から「日足のクロスのみ」へ、目標到達率の基準を 一律+5%から銘柄ごとの値へ変更したため、それ以前のシグナルと同じ数字にまとめると その的中率が何を意味するのか説明できなくなるからです。 シグナル履歴そのものはDBに残しています。
値幅の大きさやスリッページまでは考慮していない簡易的な指標です。 件数が20件に満たないソースは「参考値」と表示しています。数字が安定するまでは鵜呑みにしないでください。

目標到達率について

的中率(上記)は「1時間後/24時間後という1時点でのプラス/マイナス」しか見ていないため、 「+5%になったら売る、1〜3日以内」のような目標達成型の短期トレードを 検証するには不向きです。そこでtarget_tracker.pyが別途、シグナル発生後の 価格推移全体を追跡し、

  • 判定期間(既定72時間=3日)以内に目標%(既定+5%)へ到達したか
  • 到達した場合、何時間で到達したか
  • 到達する前に、最大でどれだけ逆行(含み損)したか
  • 到達しなかった場合、判定期間中の最大逆行はどれだけだったか

を記録しています。「到達前逆行」が損切りラインの目安(既定3%)を上回っていれば、 実際には目標に届く前に損切りしていた可能性がある、といった判断に使えます。

LONGは価格上昇率、SHORTは価格下落率を「目標方向への変化率」として同じ尺度で扱っています。 これも方向のみの簡易判定であり、実際の約定・手数料は考慮していません。投資助言ではありません。

ダッシュボードの見方

  • 資産チップ: 銘柄名をタップすると表示/非表示を切り替えられます。選択状態はこの端末のブラウザにのみ記憶されます
  • 資産の色: BTC/ETH/SOL/XRP等、銘柄ごとに固定の文字色を割り当てています
  • 方向・根拠列: 価格に加えて、判定の元になった値(RSI・クジラ検知理由・マクロパターンの統計等)を表示します。長いテキストは省略されますが、タップ/ホバーで全文が見られます
  • 直近のシグナルは、時系列を保ちつつ同じ銘柄の行がまとまるよう並び替えています

トレード記録(ジャーナル)

実際に売買した内容は自動記録できないため、journal_add.py / journal_close.py を手元のPCで実行して手動記録します。現物運用のため、記録するのは基本的にLONG(買い)エントリーのみです。 SHORTシグナルで実際に売却した場合は、そのLONGポジションの決済として記録してください。 記録後はgit pushしてリポジトリに反映しないと、このダッシュボードには表示されません。

記録した建値・損切りラインはposition_monitor.pyが30分おきに監視し、 以下のいずれかを検知するとDiscordに通知します(記録した内容を「見張り」に活かす仕組みです):

  • 利確目標(既定+5%)に到達した
  • 損切りライン(記録時に指定したstop_loss)を割り込んだ
  • 保有銘柄でテクニカル(tech)の新しいSHORTサインが出た
同一ポジション・同一種類の通知は既定12時間のクールダウンで再通知を抑制しています。 価格変動の方向・比率のみに基づく単純な判定です。投資助言ではありません。

ペーパートレード(自動シミュレーション)

実運用を始める前のデータ収集期間でも、各シグナルソースが実際に儲かる傾向にあるのかを 検証できるよう、paper_trader.pyがLONGシグナル発生のたびに実際には買わず 仮想ポジションを自動記録します(1トレードあたり想定$100分)。

  • 対象ソース: tech / dip / whale / confluence / macro(全ソース)
  • 建値は発生時の価格。損切り幅は銘柄ごとの値動きの荒さ(日次変動率)に応じて自動調整し、 利確目標は損切り幅の1.67倍に設定します(損益分岐となる勝率37.5%を全銘柄で揃えるため)
    例: BTC(日次2.3%)は損切り-2.7%/利確+4.5%、TRIA(日次6.8%)は損切り-8.0%/利確+13.3%。 以前は全銘柄一律で-3%/+5%でしたが、値動きの荒い銘柄では3%が数時間で動く範囲=ノイズでしかなく、 シグナルの当たり外れに関係なく損切りされていました。
  • 保有期限は72時間。利確にも損切りにも当たらなければ、その時点の値で決済します
    「1〜3日以内に+5%を狙う」という戦略である以上、期限内に決着しなければ 手仕舞うところまでが戦略です。これが無いと決着しないポジションが永久に残り、 「大きく動いたトレードだけ」が集計対象になって成績が偏ります。
  • 発生から60分を超えた古いシグナルは建玉しません (建値と現在価格の時間差がそのまま損益として記録され、検証が壊れるため)
  • 同じ資産・同じソースで保有中の場合は建て増ししません (1つの相場への賭けを複数トレードとして数えると、勝率も複利計算も実態から離れるため)
  • 決済はposition_monitor.pyが兼務: 利確+5%到達・損切りライン到達・ テクニカルSHORT発生のいずれかで、人の判断を待たず自動的に決済
  • 決済価格には往復手数料(既定0.3%)を織り込み済みで、成績が 実態より良く見えすぎないようにしています
  • ソース別の成績推移(今週/先週/全期間)、および「5万円スタートで複利運用したら 今いくらか」の複利シミュレーションは週次レポートで確認できます
    ※1回あたり資金の33%を投じる前提で計算しています (損失許容1%÷損切り幅3%)。以前は「毎回全額」で計算していたため、 利益も損失も過大に表示されていました(同じデータで ×0.59 → ×0.84)。 同時保有分も順番に決済したものとして扱う概算です。
2026年8月29日にペーパートレードの記録を全件リセットしました。 仕組みを導入した際、過去に溜まっていたシグナルをまとめて建玉したのですが、 建値には「シグナル発生時点の価格」を使う一方で、損益は「今の価格」と比較していたため、 26〜52時間分の値動きがそのまま損失として記録されていました (TRIAが16分で-13.5%など、市場の動きではありえない結果)。 21件すべてがこの影響を受けており、「techは負けるソース」という誤った結論が 出かかったため、データを破棄して上記2つのルールを追加したうえで測り直しています。 シグナル履歴そのもの(的中率・目標到達率)は影響を受けていません。
実トレード(journal_add.pyで手動記録したもの)とはjournalのis_paper列で 区別され、ダッシュボードの集計にも混ざりません。実運用を始めた後もペーパートレードは 並行して動き続け、「機械的に従った場合の参考成績」であり続けます。 手数料は簡易的な想定値であり、スリッページ・約定タイミングまでは考慮していません。投資助言ではありません。
※本ツールは記録・分析支援を目的としたものであり、投資助言ではありません。 自動売買は行っていません。すべてのシグナルはテクニカル指標・キーワードマッチ・統計的傾向による 簡易判定であり、将来の値動きを保証するものではありません。実際の売買判断は自己責任で行ってください。
